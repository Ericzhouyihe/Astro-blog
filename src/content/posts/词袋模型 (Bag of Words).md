在自然语言处理（NLP）的早期，计算机其实是个“文盲”。它们擅长计算数字，却完全看不懂人类写的文字。

为了解决这个问题，前辈们想出了一个极其简单粗暴，但又非常管用的办法：**把一段文本当成一袋单词。** 这就是大名鼎鼎的 **词袋模型（Bag of Words，简称 BoW）**。

##  什么是词袋模型？

用一句话解释就是：**忽略单词的顺序和语法，只统计「哪些词出现了」以及「每个词出现了几次」。**

想象一下，你把一句话里的词全部剪下来，扔进一个袋子里使劲摇晃。这时候，你再也分不清谁在谁前面，只能数数袋子里有几个“苹果”、几个“喜欢”。

###  举个最直观的例子

假设有两句话：
1. `我 爱吃 苹果`
2. `苹果 爱吃 我`

在人类看来，这两句话的意思完全不同。但在词袋模型的眼里，它们**完全一模一样**，因为袋子里装的词和数量是一样的：
- 我：1
- 爱吃：1
- 苹果：1

---

## ️ 完整分步演示

为了让你彻底弄懂，我们来看一个完整的转换过程。

### 1. 准备原始文本
- **文本A**：`猫 追 老鼠`
- **文本B**：`老鼠 追 猫 猫`

### 2. 构建词表（Vocabulary）
把两句话里出现过的所有词拿出来，去重后编个号：
> 词典 = `[猫, 追, 老鼠]`

### 3. 统计词频并转为向量
按照词典的顺序，数一数每个词出现的次数，生成数字向量：

- **文本A向量**：猫:1，追:1，老鼠:1 ️ `[1, 1, 1]`
- **文本B向量**：猫:2，追:1，老鼠:1 ️ `[2, 1, 1]`

:::tip[核心本质]
**文本 ️ 统计词频 ️ 数字向量 ️ 喂给机器学习模型**

通过这个转换，原本非结构化的文字，就变成了计算机能看懂的特征数据。早期的垃圾邮件过滤、情感分析，大量依赖这种方法。
:::

## ️ 优缺点大赏

词袋模型虽然经典，但它的缺点和优点一样明显。

###  优点
- **实现超级简单**：逻辑直观，几行代码就能搞定。
- **计算效率高**：作为 Baseline（基线模型）非常合适。

###  致命缺点
- **丢失语序信息**：`人 打 狗` 和 `狗 打 人` 的词袋向量完全一样，但意思截然相反！
- **不理解上下文**：高频但无意义的虚词（如“的”、“了”、“是”）会严重干扰结果。
- **高维稀疏**：如果词表很大，生成的向量会非常长，且大部分位置都是 0。

---

##  词袋的进化路线

为了解决词袋模型的痛点，NLP 领域开启了一场漫长的进化之旅：

1. **BoW (词袋)**：只关心“有哪些词”。
2. **TF-IDF**：给单词加上权重，削弱“的、了”等高频无用词的影响。
3. **N-gram**：不再只看单个词，而是把连续的词组合起来（如“服务很好”），开始保留一部分顺序信息。
4. **Word2Vec / GloVe**：词嵌入技术，让意思相近的词在向量空间里距离更近，保留了语义。
5. **Transformer / BERT / LLM**：现代大模型，能够结合完整的上下文语境来理解每一个词。

##  Python 极简代码实现

在 Python 中，借助 `scikit-learn` 库，实现词袋模型只需要几行代码：

```python
from sklearn.feature_extraction.text import CountVectorizer

# 1. 准备语料
corpus = [
    "猫 追 老鼠",
    "老鼠 追 猫 猫"
]

# 2. 初始化词袋模型
vec = CountVectorizer()

# 3. 拟合并转换文本
bow = vec.fit_transform(corpus)

# 4. 查看结果
print("词典:", vec.get_feature_names_out())
print("向量矩阵:\n", bow.toarray())
```
